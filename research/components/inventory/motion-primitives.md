## Integration baseline

All Core files are client-side React components styled with Tailwind CSS and, except for React itself, center on `motion/react`. The pinned repository is a Tailwind v4/React 18/Next 14 project, but the components are ordinary client components and are not inherently tied to Next.js.

Dependency shorthand used below:

- `M`: `motion`
- `CN`: upstream `@/lib/utils` helper, which requires `clsx` and `tailwind-merge`
- `LU`: `lucide-react`
- `RUM`: `react-use-measure`
- `CO`: upstream `hooks/useClickOutside.tsx`
- `PS`: upstream `hooks/usePreventScroll.tsx`
- `Portal`: `react-dom`

The upstream registry metadata is not sufficient as Taste Blocks metadata: several files import `lucide-react`, `clsx` and `tailwind-merge` without declaring all of them in their generated registry dependency lists. Derive dependencies from the pinned source, not only from `public/c/*.json`.

The component implementations contain no required bitmap or video assets. Asset warnings below concern the official demos and must be resolved with replacement content.

## Exclusions

- `Accordion`, `Dialog` and `Disclosure`: generic behavior already better owned by one shared accessible headless primitive; importing three separate hand-rolled state systems adds duplication without React-Bits-level visual value.
- `Toolbar Dynamic` and `Toolbar Expandable`: fixed demo compositions with hard-coded content, not reusable component APIs. Generalizing them would be original implementation work and must not be represented as a copied component.
- Everything under `components/website/`: documentation-site infrastructure, not distributable motion components.
- Every file under `app/docs/**` as a separate catalog count: these are usage examples and variants of the 33 Core files.
- `public/*` demo images and logos: not needed by component implementations and not cleared for Taste Blocks redistribution.
- Motion Primitives Pro: redistribution and competing kits are expressly prohibited by its separate license.

## Import gate

Before any of the 28 candidates can become `verified`:

1. Copy only from the pinned Core path and record the original SHA/path.
2. Include the Motion Primitives MIT notice and note every local change.
3. Replace demo media with Taste Blocks-owned assets.
4. Correct registry dependencies from actual imports.
5. Add the listed reduced-motion fallback.
6. Run keyboard, touch, coarse-pointer, screen-reader structure, TypeScript, production-build and console checks.
7. Reject the candidate rather than silently redesigning it if the required repair becomes a substantially new component.
